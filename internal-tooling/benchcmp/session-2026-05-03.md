## Remaining clusters

### Cluster A — `s = s[k:]` byte-scan loops (loopheapify bails on OSLICESTR)
6+ benchmarks (utf8 ValidString, strings TrimASCII, path/Match, path/filepath/Match) still 4-27× slower because `loopheapify.go:43-44, 257-262` puts `OSLICESTR` in the bail set. The pass now defaults on, so the only blocker is teaching it to refresh `__heap` after every `s = s[k:]` reassignment, or alternately recognising the canonical `for len(s) > 0 { … s = s[k:] }` cursor pattern. Estimate: ~150-300 LOC + soak. Not blocked on a design decision.

**Negative result from this session**: I prototyped the obvious extension — detect `s = s[k:]`, substitute `s → __heap` everywhere in the loop body so the assignment becomes `__heap = __heap[k:]`. Correctness held (TestReplacer + std test sweep green) but **the perf win didn't materialise**: ValidString stayed at 42 µs vs the 1.5 µs stock target. Root cause is that `loopheapify`'s dispatch elimination relies on the `StringWord2(StringMake) → Const64` SSA rewrite chain, which sees the freshly-built `__heap` from `unsafe.String(unsafe.StringData(s), len(s))` as an `OpStringMake` with a constant zero-tag word2. After `__heap = __heap[k:]` the value is no longer an `OpStringMake` (it's a slice-of-string), so subsequent `OINDEX(__heap)` reads still emit the SSO dispatch. Two ways to actually win the cluster:
  - Extend the SSA rewrite chain so a slice of an `OpStringMake` propagates the zero-tag invariant.
  - Switch the loop transformation to an offset/cursor instead of re-slicing `__heap`: keep `__heap` constant, track a counter, rewrite `OINDEX(s, j)` to `OINDEX(__heap, off+j)` and `s = s[k:]` to `off += k`. Larger change but doesn't depend on the SSA chain handling slices.

### Cluster B — `reflect.Value` in tight loops (fat-iface unpack)
~10+ benchmarks (`reflect.DeepEqual/*`, `reflect.IsZero/*`, `encoding/binary.AppendSlice1000Structs`, `fmt.ScanInts`, `fmt.ScanRecursiveInt`, `errors.As`) regress 25-560%. Root cause: `reflect.ValueOf` boxes the empty interface and copies the 16-B inline payload into `Value.inline` (`src/reflect/value.go:248-267`); every `Field`/`Index`/`Type` returns a fresh fat-iface header. **Blocked on a design decision**: either revert `reflect.Value` to a 16-B (typ, ptr, flag) layout with an on-demand heap shadow for inline-rep types, or add a parallel `IndexInline`/`FieldInline` family. Estimate: 200-1000 LOC + soak. Tracked in `project_fat_iface_alloc_regression.md`.

### Cluster C — short-string `==` in tight loops (SSO 3-word fast path tax)
3 `net/http.FindChild/*linear` sub-benchmarks. `9d5af1a423` already removed the largest spike (147 -> ~95 ns/op on n=32) but stock is still 26.6 ns/op so we are at +250% rather than +450%. Remaining work: inline `streqfast` body so the SSO-bit test stays in a register. Estimate: ~50-150 LOC in `cmd/compile/internal/ssagen/ssa.go`. Not blocked.

### Cluster D — heap-rep string conversion in encode/decode hot paths
`encoding/gob.EndToEndSliceByteBuffer`, `encoding/gob.EncodeInterfaceSlice`, `encoding/json.CodeUnmarshal{,Reuse}`, `net/url.EncodeQuery`, `fmt.ScanRecursiveIntReaderWrapper`. Two structural causes (see next section). EncodeQuery has a small isolated fix (~30 LOC); the rest are blocked on the SSO header size.

### Cluster E — `encoding/json` type-fields cache
Single benchmark (`TypeFieldsCache/MissTypes100000`): +18.8% ns / +22% B. Cache values contain string keys; the 24-B SSO header per cached entry multiplies into the +22% B. Same blocker as cluster D — fundamental, waits on SSO Phase D.

## Allocations: why some benchmarks still allocate more

Two structural reasons survive cluster-by-cluster across the regression list.

### 1. 24-B SSO heap-rep header (vs stock's 16 B) widens any container of strings by 1.5×
- `encoding/json.BenchmarkCodeUnmarshal`: stock 1.9 MB / 39 990 alloc → gd 2.1 MB / 38 089 alloc (+9.1% B / -4.8% alloc; the +180 KB is the wider header times the per-decode object graph).
- `encoding/json.BenchmarkCodeUnmarshalReuse`: +0.4% B but the hot-path string fields each grow 50%, so the per-iter cache pressure shows up as +22% wall-time.
- `encoding/json.BenchmarkTypeFieldsCache/MissTypes100000`: stock 95.9 MB → gd 117.3 MB (+22% B, +18.8% ns) — almost entirely the wider SSO header on every cached field name.

### 2. Boxing a SSO heap-rep string into a 32-B fat-iface duplicates the header
- `errors.BenchmarkAs`: stock 40 B / 2 alloc → gd 120 B / 3 alloc (+1 alloc / +80 B). The extra alloc is `errorT.s string` boxed into a fat-iface at `src/errors/wrap.go:124` (`target.Elem().Set(reflectlite.ValueOf(err))`).
- `net/url.BenchmarkEncodeQuery/oe=utf8&q=puppies`: stock 56 B / 3 alloc → gd 104 B / 4 alloc (+1 alloc / +48 B). `QueryEscape` returns a SSO heap-rep string that is then boxed into `iface{}` for `buf.WriteString`; the argument-stack widening copies the SSO inline bytes.
- `encoding/gob.BenchmarkEndToEndSliceByteBuffer`: stock 13.4 KB / 302 alloc → gd 12.0 KB / 202 alloc — alloc count is *down* 33%, but the boxed-iface cost shows up as +25% wall-time.

## Recommended follow-ups, ranked by leverage

1. **`reflect.Value` layout fix** — deepest single win. Affects all `reflect.DeepEqual/*`, `reflect.IsZero/*`, `encoding/binary` reflect path, `fmt.Scan*`, `errors.As`. Estimate: 200-1000 LOC + soak. Blocked on layout decision (16-B revert vs new fast-path family).
2. **SSO Phase D 12-B header** — kills clusters D and E plus the +1.5× tax on every string-bearing container fork-wide. Multi-week, touches everything; tracked under `reference_sso_string_plan`.
3. **loopheapify OSLICESTR / `s = s[1:]` support** — fixes 6+ benchmarks (utf8 ValidString family, strings TrimASCII, path/Match, path/filepath/Match) currently 4-27× regressed. Estimate ~150-300 LOC in `cmd/compile/internal/loopheapify/loopheapify.go` plus soak. Highest leverage of the easy wins.
4. **`encoding/binary` struct-of-scalars fast-path** — single benchmark (`AppendSlice1000Structs`, +400%) but isolated and avoids the reflect tax entirely. ~200 LOC + a small code generator next to `encodeFast` (`src/encoding/binary/binary.go:491-`).
5. **`net/url.EncodeQuery` in-place escape** — ~30 LOC, single benchmark. Add `appendEscape(dst []byte, s string, mode encoding) []byte` and route `Values.Encode` through it; removes the per-call SSO box.

## Open questions for next session

The two highest-leverage items are deep and contend for the same engineering budget. **Reflect.Value rework** affects ~10 hot benchmarks across reflect/binary/fmt/errors with 3-6× regressions; **SSO Phase D** affects every long-string container in the fork (json cache, gob, maps of strings) at a smaller per-benchmark scale but much wider blast radius. If the goal is removing the worst regressions from the top-30 table, reflect goes first (those are 5 of the worst entries). If the goal is reducing fork-wide RSS / B-per-op, SSO Phase D is the bigger structural win.

Secondary question: cluster A is the easiest big-impact item (~150-300 LOC, no design lock) and would unblock 6 benchmarks immediately. Worth doing as a warm-up before either of the above?
